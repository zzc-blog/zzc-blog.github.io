Termux 完整使用笔记

发表于2026-07-29|更新于2026-07-29|其他科研
|总字数:5.5k|阅读时长:25分钟|浏览量:

Termux 是安卓无 root 运行的 Linux 终端模拟器，可将手机变为便携式 Linux 服务器。
不要安装 Google Play 旧版，建议从 F-Droid / GitHub Releases 下载最新 APK。
安卓版本要求 Android 7.0+。

3.5 重要注意事项

  • Termux 环境独立，不能直接运行安卓 APK，它是 Linux 环境，不是安卓 shell。
  • 不要使用 sudo，Termux 没有真正 root；需要 root 需手机本身已 root。
  • 卸载 Termux 会清空全部内部数据，提前备份重要文件。
  • 不要随便复制网上来路不明的脚本直接执行，有风险。

问题 根因 解决
控制台资源加载失败 9000/9001 分离，需不同子域名 双子域名 + ingress 分别路由

图片直链 403 匿名无读取权限 mc anonymous set download

10.7 更推荐的做法：Android 宿主装 Tailscale App

直接在手机上安装 Tailscale App，使用 TUN 模式（无需在 proot 容器内折腾），优势明显：

对比项 容器内 userspace 模式 Android App TUN 模式
虚拟网卡 ❌ 无 ✅ 有
ping 响应 ❌ 不响应 ICMP ✅ 可响应
端口转发 需 serve 显式转发 ✅ 自动路由
保活 需 termux-wake-lock ✅ 系统级 VPN
性能 用户态，损耗大 ✅ 内核态

手机上 Tailscale App 连接后，Ubuntu 容器内监听 0.0.0.0 的服务（Nginx、MinIO 等）自动暴露在手机的 Tailscale IP 上。

10.9 Tailscale 为什么快？

维度 Tailscale 传统 VPN
数据路径 设备间 P2P 直连 全部经过中心服务器
加密 WireGuard（4000 行代码） OpenVPN（10万行）
吞吐量 同硬件下 OpenVPN 的 3-4 倍 基准
延迟 ≈ 实际网络延迟 多一跳中心服务器

三种连接模式性能差异：

模式 路径 性能
Direct（直连） 设备 ⇄ 设备 ✅ 延迟最低，吞吐最高
Peer Relay 通过 tailnet 内另一台设备中转 ⚠️ 多一跳，仍可控
DERP Relay 通过 Tailscale 官方节点中转 ❌ 延迟高，国内尤其慢

10.10 提速方案

  1. 路由器放行 UDP 41641 端口 → 提高打洞成功率
  2. 自建 DERP 中继 → 用一台国内 VPS 部署 derper，国内延迟从 200ms+ 降到 30ms
  3. 配置 Peer Relay → 在 tailnet 内指定一台网络条件好的设备作为中继

十二、常见问题与边界

12.1 pkg update 报网络超时

12.2 找不到手机文件

确认运行过 termux-setup-storage 并授予存储权限，文件在 ~/storage 下。

12.3 pip 安装报错

12.4 proot 环境的硬限制

❌ 不能做的 原因
Docker 守护进程 缺少 cgroups/namespace
systemd 没有真正的 init 系统
加载内核模块 用户态环境
真 root proot 的 root 是模拟的
Snap 包 依赖 systemd
GPU 加速 / USB 直通 无硬件直通能力

12.5 性能预期

任务类型 性能损耗
CPU 密集型 12-18%
I/O 密集型 30-50%
网络密集型 较小

12.6 安全提醒

  • 不要用 root 账号配置 PicGo 等外部工具 → 创建专用用户，最小权限原则
  • 定期更换密码
  • Cloudflare Tunnel 图床需关闭缓存（Bypass cache）
  • 时间同步：确保 Ubuntu 容器时间误差 < 15 分钟，否则 S3 签名会失效
  • 不要在 Termux 中随意执行来路不明的脚本
