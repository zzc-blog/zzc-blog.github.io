GitHub 图床 + Cloudflare Worker 加速代理

发表于2026-07-30|更新于2026-07-30|GitHub
|总字数:785|阅读时长:4 分钟|浏览量:

本文记录用 Cloudflare Worker 反代 GitHub 图床的完整方案，涵盖 Worker 部署、PicGo 配置与 jsDelivr 备用线路。

1. 基础环境信息

项目 值
GitHub 图床仓库 zzc-blog/img-bed
目标分支 main
Worker 访问域名 https://img.zzc.dpdns.org
核心作用 反向代理 raw.githubusercontent.com，解决国内 DNS 污染、图片无法直连问题；搭载 Cloudflare 边缘缓存，加速图片访问

2. Cloudflare Worker 最终运行代码

3. Worker 部署操作流程

  1. 登录 Cloudflare 控制台，找到【Workers & Pages】，点击【创建应用程序】→【创建 Worker】
  2. 自定义 Worker 名称，完成初始部署，进入【快速编辑】页面
  3. 删除编辑器内全部默认代码，粘贴上方完整代码
  4. 点击【保存并部署】
  5. 进入【设置】→【触发器】→【添加自定义域】，绑定域名：img-proxy.zzc.dpdns.org

4. 问题踩坑汇总

报错 Error 1101 Ray ID

  • 原因：原始代码使用 ctx.waitUntil，在自定义域名环境容易触发运行异常。
  • 解决方案：移除 ctx.waitUntil，缓存逻辑单独封装异常捕获，缓存失败不中断图片正常访问。

访问返回 502 Proxy Error

  • 原因：Cloudflare 边缘节点无法连通 raw.githubusercontent.com，属于网络限制，代码无法彻底解决。

⚠️ raw.githubusercontent.com 原生链接国内无法打开，必须依靠代理或者 CDN 中转。

自定义域名 https://img.zzc.dpdns.org

⚠️ 重要提醒：自定义域名末尾不要添加斜杠 /

7. 使用注意事项

  • 长效缓存生效后，不要在 GitHub 仓库直接覆盖同名图片，CDN 不会主动刷新缓存；建议修改文件名重新上传
  • Cloudflare Worker 免费方案配额：每日 100,000 次请求，个人博客图床场景足够使用
