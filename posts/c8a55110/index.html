1.2 Magisk 开机脚本 chroot_server.sh

宿主机（Android）侧，Magisk 开机脚本位于 /data/adb/service.d/chroot_server.sh：负责挂载必要目录、写入 DNS、拉起 chroot 内的 /opt/start_all.sh。

说明：仅挂载必要目录并调用 /opt/start_all.sh，本身保持简单、不阻塞 Magisk 启动流程。

1.3 chroot 统一启动脚本 start_all.sh

chroot 内（先 chroot /data/linux /bin/bash）的 /opt/start_all.sh 负责启动所有服务并进入保活循环。

要点：

  • 已去掉 exec /bin/bash，改为 exit 0，避免阻塞 Magisk 脚本。
  • 增加了 AList 端口二次确认循环（最多等待 6 秒），解决开机时 AList 启动慢的问题。
  • 保活循环在后台运行，不影响脚本退出；保活判断用全路径匹配，避免与其他同名进程混淆。
  • 预留了 Node.js 应用启动注释行，按需取消注释。
  • 后续各服务（如 frpc）的启动与保活统一在此脚本中追加，见 第八章。

3.9 排错

  • node: command not found：检查 /usr/local/bin/node 是否存在，ls -l /usr/local/bin/node 是否指向正确的 /opt/node/bin/node。
  • libstdc++.so.6: version GLIBCXX_3.4.29 not found：Ubuntu 22.04 自带 libstdc++6 较新，一般没问题；若出现执行 apt install -y libstdc++6。
  • npm 安装包报权限错误：全局安装时不要用 sudo（chroot 内已是 root）；若使用非 root 用户，需 npm config set prefix /home/user/.npm-global 并调整 PATH。

四、SILO 对象存储安装配置

返回目录

环境约定：chroot（Ubuntu 22.04 ARM64，无 systemd）＋ SILO（PGSTY SILO，MinIO 社区分支）＋ 9000 S3 / 9001 控制台 ＋ 数据 /data/silo ＋ 账号 zzc ＋ init.d 自启 ＋ 日志 /var/log/silo.log。

SILO 是 S3 兼容对象存储，arm64 有官方二进制；9000 是 API、9001 是 Web 控制台，用 MINIO_ROOT_USER/MINIO_ROOT_PASSWORD 和 server /data --console-address :9001 启动。

如果你 /usr/local/bin/silo 其实不是 PGSTY SILO，而是别的自研二进制，把「下载/启动参数」那段替换成你自己的即可，init.d 模板通用。

4.9 常见排错

  • 9000/9001 只监听 127.0.0.1：检查是否加了 --address 127.0.0.1:9000；要局域网访问用 :9000、:9001 全网卡。
  • 日志报 Invalid Argument / 时间相关签名失败：chroot 内装 ntp 或确保手机系统时间准；S3 签名对时钟敏感。
  • 密码太短起不来：root 密码至少 8 位。
  • init.d start 后立刻退出：tail /var/log/silo.log；多为 /data/silo 权限或 USER 不存在，用 root 跑可先排除权限问题。
  • 与旧 minio 数据共存：SILO 保留 .minio.sys 格式，旧 minio 数据目录可直接当 /data/silo 挂；但版本跨度大先备份。

5.7 消除 qBittorrent / Transmission / aria2 三条 WARN

AList 启动报这三条，通常是因为代码里内置了离线下载器初始化、但本机没装对应客户端。不装就不用管；想彻底不提示/不初始化：

  1. 不安装 aria2、qbittorrent、transmission（已经没装就跳过）。
  2. 后台 → 管理 → 设置 → 其他：
    • Aria2 RPC 留空（不填 http://127.0.0.1:6800/jsonrpc）
    • Qbittorrent url 留空（默认预设是 http://admin:adminadmin@localhost:8080/，不配即不连）
    • Transmission 相关 RPC/临时目录留空
    • 离线临时目录（aria2/qbittorrent）留空
  3. 只用 SimpleHttp 离线（本机直链拉取）或不开放离线功能：文件列表右下角离线按钮可不用；若不想任何离线，不挂离线存储即可。
  4. 若日志仍 WARN，确认是「未找到客户端」类，可忽略；只在不影响 5244 监听的情况下不处理。

以后真要离线再装 aria2：

再在 AList 其他设置填 Aria2 RPC 即可。

5.8 Nginx 反代 + HTTPS（可选）

要 HTTPS：certbot --nginx -d alist.example.com，并把 AList 后台「站点 URL」改成 https。

5.9 排错

  • 5244 起不来：tail /var/log/alist.log；多是 data 目录权限、端口被占、config 损坏。chroot 内用 root 跑基本排除权限问题。
  • 改了配置不生效：/etc/init.d/alist restart，别只 reload nginx。
  • 忘记 admin 密码：cd /opt/alist && ./alist admin random 或 set 新密码。
  • 启动特别慢/卡「storage loading」：某些云盘 token 失效，用 ./alist storage list 查、storage disable /挂载路径 禁掉再起。
  • 全网卡不通但 127 通：检查 alist 是否被人改过绑定地址；默认就是 0.0.0.0:5244，不用特配。

7.3 前台先跑看日志

正常会看到类似 start proxy success / proxy [zzc-nginx-tcp] tcp local_port 80 ...，然后用外网 http://服务器地址:remote_port 访问。

常见报错对照：

  • dial tcp x:7000 i/o timeout → 控制面板地址/端口错，或 chroot 出网被挡；先 nc -vz 服务器地址 7000 测
  • authorization failed / token error → ini 的 token 和面板不一致，复制粘贴，别加空格
  • port already used / remote port x already registered → 换 remote_port 或在面板改端口
  • login fail 但网络通 → server_port 不对、token 错、服务端没起对应协议
  • 启动成功但浏览器打不开 → 查 nginx 本地 curl 127.0.0.1 是否还显示默认页、local_ip 是否填错、面板隧道是否「在线」

7.4 确认 nginx 本地先通

如果本地还是 nginx 默认页而不是博客，先按第二章把 default site 删了、sites-enabled 只留 zzcblog、nginx -t && service nginx reload，再测 frpc。
